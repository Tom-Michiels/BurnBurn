# IM03 Documentcommands en undo

Status: gereed voor poort A-basis (macOS arm64, headless). Windows: onbevestigd (geen runner).

## Opgeleverd (`burnburn-document`, laag 2)
- `DocumentSnapshot` (immutable, `Arc<BTreeMap<GeometryId, Arc<GeometryObject>>>`, goedkoop te klonen;
  `from_parts(objects, next_id)` voor open/recovery met `SnapshotError::{DuplicateId, IdNotBelowNext}`).
- `GeometryObject` (id, naam, `ObjectKind`, `GeometrySource::{Drawn, Imported{asset: ContentHash, entity}}`,
  `Arc<Path>` in wereld-mm).
- `DocumentCommand { document, expected, request, payload }`, `CommandPayload::{CreateRectangle, SetDimension,
  Transform, Delete, Rename}`, `CommandOutcome { previous, revision, changes: ChangeSet, warnings, undo_label }`,
  `CommandError` (o.a. `StaleRevision`, `WrongDocument`, `UnknownGeometry`, `InvalidValue`), `UndoLabel`.
- `DocumentSession`: `apply`, `undo(expected)`, `redo(expected)`, `undo_label/redo_label`, `can_undo/can_redo`,
  `is_dirty`, `mark_saved(at)`, `from_snapshot`.
- In `burnburn-types` toegevoegd: `DocumentId`, `RequestId`, `ContentHash` (+`HashParseError`).

Ontwerpkeuzes: undo bewaart voor/na-snapshots (geen inverse commands), dus herstel van inhoud en identiteit is
structureel. Undo/redo geven een **nieuwe** revisie (contracts.md). De id-teller gaat bij undo nooit terug.
`is_dirty` vergelijkt de inhoud-`Arc` met de bewaarde (undo naar bewaarde inhoud = schoon).
