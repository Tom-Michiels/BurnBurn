# IM16 Transport en machineactor — eerste deel (`burnburn-machine`)

Status: execution-state machine zonder live IO gereed (macOS arm64). Geen UDP-adapter in deze ronde; tests gebruiken
`burnburn-test-support::{FakeClock, ScriptedPeer}` via een kleine test-adapter (`FakePort`) in `tests/execution.rs`.
Geen test contacteert een echte laser of socket.

Commando's: `export PATH="$HOME/.cargo/bin:$PATH"; CARGO_TARGET_DIR=target/protocol cargo test -p burnburn-machine`.

## API (kort)
- `MachineId`, `MachineIdentity { id, model: Option, firmware: Option }` (niet geraden), `ExecutionId`.
- `ControllerPort` (send / non-blocking `try_recv` / `reconnect`), `Envelope { to, tag, request }`,
  `RequestTag { execution, epoch, seq }`, `Incoming { from, tag, reply }`, `Request` (`UploadChunk`, `QueryStored`, `Start`,
  `QueryStatus`, `Stop`; alleen queries `is_idempotent`), `Reply` (`Ack`, `Nak`, `Err`, `Stored(bool)`, `Status(..)`).
- `ExecutionActor<P>`: `new(identity, port, Arc<dyn Clock>, Policy)`, `begin_upload`, `confirm_stored`, `start`, `query_status`,
  `cancel`, `reconnect`, `poll`; `execution()` met `ExecutionState` en tijdgestempelde `Evidence`; `ignored()` voor niet-toe te wijzen antwoorden.
- `ExecutionState`: `Uploading{acked,total}`, `UploadAcked`, `Stored`, `StartRequested`, `Running`, `Completed`,
  `Unknown(UnknownReason)`, `Failed(FailReason)`, `Cancelled`.
- Regels: ACK ≠ Stored (alleen read-back `Stored(true)`); Start vereist `Stored`, wordt hoogstens één keer verstuurd
  (`start_sent` blijft waar); verloren/negatief startantwoord → `Unknown`; Completed alleen na `Running` + `Finished`-status;
  één request in flight; vóór elk nieuw request worden al wachtende (verouderde) antwoorden weggegooid; reconnect = nieuwe epoch;
  begrensde retries alleen voor queries (`Policy::max_query_attempts`), timeouts via geïnjecteerde klok.

## Open / onbevestigd
- Geen live IO: Ethernet/UDP-adapter (poorten 50200/40200, 1470-bytechunks, ACK-normalisatie via `burnburn_ruida::udp`) volgt;
  nooit tegen een echte laser in tests.
- Toewijzing van antwoorden zonder sequentienummer op de wire: een duplicaat-ACK die pas ná het volgende request binnenkomt is
  op Ruida-UDP niet te onderscheiden; de actor gooit alleen al wachtende antwoorden weg. Gedrag op hardware/emulator te meten.
- Hoe `Stored` op de controller wordt bewezen (bestandslijst/read-back), statusbits voor `Running`/`Finished`, betekenis van
  NAK/ERR bij start: firmwareafhankelijk en niet bevestigd (daarom NAK/ERR op start → `Unknown`).
- Timeout- en retrywaarden in `Policy::default()` zijn plaatshouders, geen gemeten LightBurn-/firmwarewaarden.
- Cancel na start stuurt één `Stop` en blijft `Unknown(StopRequested)`; bevestiging van stop en Unknown-reconciliatie horen bij IM17.
- Een `Unknown`-execution blokkeert een nieuwe upload (`Busy`) tot expliciete reconciliatie (nog geen API).
- Machine-identiteit: model/firmware blijven `None` tot een probe (nog niet geïmplementeerd).

# IM16 vervolg (fase C, 18-10-2026) — DR-10, identiteit, laser-uit-framing, `burnburn-runtime`

Status: groen op macOS arm64. Geen enkele test contacteert een laser of netwerkapparaat: live UDP alleen tegen een
fake-controllerthread op `127.0.0.1:0` in het testproces. Hardwarestatus: **onbevestigd** (zie `docs/hardware/evidence.md`).

Commando's: `export PATH="$HOME/.cargo/bin:$PATH"; CARGO_TARGET_DIR=target/protocol cargo test -p burnburn-machine` resp.
`-p burnburn-runtime` (`--test <bestand>` per rij).

## API (kort, nieuw)
- `ExecutionId` opaak (`from_raw`/`raw`, `Display` "exec-N"; `compile_fail`-doctest op `ExecutionId(7)`).
- `RdArtifact::from_rd_file(plan, rd_bytes, max_chunk)` berekent `rd_hash = ContentHash::of(Rd, bytes)` en splitst
  ongewijzigd; `begin_upload(id, &RdArtifact)`; `Execution { plan, rd_hash, .. }`; `Evidence::StorageConfirmed { rd_hash }`.
- Identiteit vóór elke upload: `Request::QueryIdentity` → `Reply::Identity(ControllerIdentity)`; toestand
  `VerifyingIdentity`; mismatch → `Failed(IdentityMismatch)`, onbeantwoord → `Failed(IdentityUnconfirmed)`; profiel zonder
  model/firmware → `ActorError::IdentityNotConfigured`. Geen jobbyte vóór een passend antwoord.
- `begin_reverify(id, &RdArtifact)`: identiteit + read-back van een eerdere upload (nieuwe sessie), toestand `Reverifying`,
  verstuurt nooit jobbytes; alleen `Stored(true)` maakt `start()` mogelijk.
- `frame_plan(&JobPlan, &FrameOptions) -> FramePlan` (in `burnburn-machine`, zie afwijkingen): één settingsblok met
  vermogen 0, alleen `Travel` langs `plan.bounds()` (incl. overscan), terug naar de eerste hoek.
- `PortError::{NotSupported, QueueFull}`; `impl ControllerPort for Box<P>`.
- `burnburn-runtime`: `SystemClock` (monotoon, `Instant`), `RuidaUdpPort` (`std::net`, eigen ontvangstthread, begrensde
  `sync_channel`, alleen de geconfigureerde peer; broadcast/unspecified/multicast/poort 0 → `NotSupported`; vreemde
  afzenders genegeerd en geteld in `UdpStats`), `WireDialect` + `NoVerifiedDialect` (alleen RD-chunks en 1-byte
  ACK/NAK/ERR/ENQ; al het andere `NotSupported`), `UsbPort::open` → `NotSupported`, `MachineDriver` (historie vóór actor,
  zie IM17), `StdJournalFs`, `SystemWallClock`.

## Afwijkingen van contract (ter review Design, ook in `docs/coordination/protocol.md`)
- Pakket-retries: de actor herhaalt **geen** chunk na verloren ACK (strenger dan "begrensd zelfde pakket opnieuw"); een
  half-geüploade job is `Unknown` (research 03-transport §Verlies). Start nooit opnieuw.
- `IdentityMismatch` is een `ExecutionState::Failed(..)` met bewijs i.p.v. een `ActorError` (het antwoord komt asynchroon).
- `frame_plan` staat in `burnburn-machine::frame`, niet in `cam` (andere eigenaar); `ruida::lower_frame` is niet nodig:
  het frameplan bevat alleen `Travel` en vermogen 0 en gaat door de bestaande `lower`. De test decodeert de geüploade bytes
  met de eigen decoder, **niet** met de Python-oracle. `frame_is_rejected_when_profile_lacks_verified_frame` ontbreekt
  (er is nog geen capability-matrix in het profiel).
- Live UDP-tests achter `BURNBURN_HW_MACHINE` bestaan niet: er is geen geverifieerd dialect om mee te testen.

## Onbevestigd
- Elke wire-vorm behalve RD-chunks + checksum en 1-byte ACK/NAK/ERR/ENQ (OSS-beschreven, geen capture): identiteit,
  read-back, status, start, stop. `NoVerifiedDialect` weigert ze; de CLI weigert daarom upload/start in productie.
- Of meerbyte-antwoorden een checksum dragen (aangenomen: niet; ongescrambeld aan het dialect gegeven).
- Poorten 50200/40200, 1470-bytechunks, timeouts (`Policy::default()`), ICMP-gedrag bij verdwenen controller.
- Laser-uit-framing op hardware (of de buis bij vermogen 0 echt uit blijft) — nooit gemeten.
- Alleen macOS arm64; Windows-socketgedrag niet getest.
