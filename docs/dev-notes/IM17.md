# IM17 Bevroren jobs en historie (`burnburn-history`, ADR 0008)

Status: groen op macOS arm64. Alle IO via de `FileSystem`-poort (io, C-7); tests gebruiken io's `MemoryFileSystem`
met een kleine wrapper (`tests/common/mod.rs`) die `append` met "gescheurde append"-injectie levert, omdat
`MemoryFileSystem::append` bij Kern nog in de rode fase stond. Productie: `burnburn_runtime::StdJournalFs`.

Commando's: `export PATH="$HOME/.cargo/bin:$PATH"; CARGO_TARGET_DIR=target/protocol cargo test -p burnburn-history`
(`--test jobs|journal|executions|calibration|settings`), runtime-deel: `cargo test -p burnburn-runtime --test driver`.

## API (kort)
- `History::open(fs, dir, &JournalLimits) -> (History, RecoveryReport)`; maakt niets aan. `append(fs, record, at)` =
  `append` + `sync_file`, pas daarna geïndexeerd; `put_blob`/`read_blob` (blobs `blobs/sha256-<hex>`, sleutel
  `ContentHash::of(Asset, bytes)`, atomair schrijven, hash bij lezen herberekend → `BlobMismatch`).
- Journalformaat volgens contract: segmentkop `BBJ\0 ‖ u16 1 ‖ u16 0`, record `0xB0B04A31 ‖ len ‖ crc32 ‖ JSON`
  (`{"schema":1,"seq":…,"wall_time":"RFC3339","kind":…,"body":…}`), nieuw segment via temp + sync + replace + dir-sync,
  rotatie na ≥ `max_segment`. Herstel: staart → `TornTail` (blijft staan, volgende append in nieuw segment);
  schade met data erachter, niet-stijgende `seq` of onbekend `schema` → `read_only` + `Corrupt`; onbekende `kind` →
  `HistoryRecord::Unrecognized` (bewaard, telt niet).
- `record_compiled(fs, CompileRecord { plan, rd_file, project, project_path, preflight, profile }, at)` → blobs
  (plan-JSON, RD-bytes, projectcontainer) vóór `JobCompiled`; weigert preflight-fouten. `load_plan` bouwt het plan via
  `JobPlanBuilder` opnieuw en vergelijkt de id; `load_rd` controleert `rd_hash`; `load_artifact` → `RdArtifact` (nooit
  hercompileren).
- `CompiledJobId = ContentHash::of(HistoryRecord, tag("compiled-job") ‖ plan ‖ rd ‖ profile.content)` (tot
  `HashDomain::CompiledJob`, C-5, er is).
- `enqueue`/`change_quantity` (nooit onder completed), `create_execution(…, current_profile)` (weigert
  `ProfileChanged` als `content` verschilt), `record_intent` (`IntentReceipt { fresh }`, herhaalde `ActionId` = no-op),
  `observe(fs, &machine::Execution)` (nieuwe evidence 1-op-1 + `StateObserved`), `reconcile_by_operator` (alleen vanuit
  `Unknown`; alleen `RanToCompletion` telt), `queue_counts`, query's per project (`project_hash`) en per machine,
  `next_execution_id` (max+1 over herstarts), `record_settings_backup`/`settings_backups` (IM29).
- Na `open` is elke niet-terminale execution `Unknown { InterruptedByRestart }` (`RecoveryReport::interrupted`).
- `burnburn-runtime::MachineDriver`: `upload`/`confirm_stored`/`reverify`/`start`/`query_status`/`poll`; elk intent
  durable vóór de actor het krijgt; start geweigerd als de historie al een start-intent heeft (ook na herstart) of als
  er in deze sessie geen vers `Stored`-bewijs is.

## Afwijkingen / open
- `CompiledJob.plan` is de `ContentHash` van de `JobPlanId` (job heeft geen constructor uit een hash; het plan-blob bewijst het).
- `TornTail` wordt ook in een **niet-laatste** segment geaccepteerd als er niets meer achter de kapotte record staat: de
  eigen regel "volgende append in een nieuw segment" zou anders bij de volgende open `Corrupt` geven. Voorgelegd aan Design.
- Na elke CLI-aanroep (nieuw proces) is een gestarte execution `Unknown { InterruptedByRestart }`; reconciliatie via
  statusquery (`ReconcileBasis::StatusQuery`) is als type aanwezig maar niet geïmplementeerd: er is geen geverifieerde
  statusbetekenis. Alleen operatorbevestiging.
- `HistoryStore`-poort in presentation bestaat nog niet (User-flow); presentation gebruikt de historie dus nog niet.
- Geen fuzz-target `History::open` (Testing); de prefix-test dekt afkappen, niet willekeurige bytes.
- Meetcriterium ADR 0008 (open + index 100 000 records < 500 ms) niet gemeten.

## Onbevestigd
- Crashgedrag op echte schijf (power-cut) — alleen het `MemoryFileSystem`-model en `StdJournalFs` in een tempdir.
