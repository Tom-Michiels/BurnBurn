# IM04 Projectopslag en recovery

Status: gereed voor poort A-opslag (macOS arm64). Windows-replace/-sync: onbevestigd (geen runner).

## Opgeleverd
- `burnburn-types`: `CanonicalEncode`/`CanonicalWriter`/`NonFiniteValue` (ADR 0004-codering); `ContentHash` (IM03).
- `burnburn-geometry`/`burnburn-document`: `CanonicalEncode` voor `Path`/`Subpath`/`Segment` en `GeometryObject`;
  `Subpath::new`/`Path::from_subpaths` (exacte reconstructie zonder builder-tussenlijnen).
- `burnburn-io` (nieuw, laag 4):
  - `fs::FileSystem`-poort (stappen apart: `create_temp_in`, `write_all`, `sync_file`, `replace`, `sync_dir`, …),
    `FsError { op, path, kind }`.
  - `std_fs::StdFileSystem` (echte adapter) en `memory::MemoryFileSystem` (foutinjectie `fail_on(op, skip)`, gescheurde
    write, `simulate_power_loss`, operatielog).
  - Container v1 = zip (`zip` 9.0.5 zonder default-features): `manifest.json`, `document.json`,
    `assets/sha256-<hex>`, `previews/…` genegeerd. Vaste entryvolgorde en tijdstempel → deterministische bytes.
    Leesgrenzen: 4096 entries, 64 MiB JSON, 1 GiB per asset, 2 GiB totaal; onbekende/traversing entries geweigerd.
  - `dto::v1` los van domeintypen, `deny_unknown_fields`; `Num` accepteert `null` zodat NaN als
    `InvalidValue { path }` gemeld wordt. Versiepoort vóór strikte parse: `schema > 1` → `NewerSchema`.
  - `save_project` (temp → write → sync → replace → sync dir; valideert eerst via decode; `SaveError::Unconfirmed`
    als alleen de dir-sync faalt), `load_project`, `write_recovery`/`read_recovery`/`discard_recovery` (eigen map,
    zelfde formaat), `project_hash` (domein `project`, zonder uuid/next_id/opmaak), `asset_hash` (domein `asset`).
  - `Project { uuid: ProjectUuid, document: DocumentSnapshot, operations: Vec<OperationPlaceholder>, assets: AssetStore }`.
    **`OperationPlaceholder` (id, naam, targets) is een tijdelijke structuur tot IM13**; ids delen de project-
    id-ruimte (uniek, ≠ geometrie-id, < `next_id`), targets moeten bestaan.
- Fixture `test-data/projects/v1/rectangle-120x80.burnburn` met `manifest.json` (SHA-256, herkomst) en README.

## Verificatie
- `cargo clippy -p burnburn-types -p burnburn-geometry -p burnburn-document -p burnburn-io --all-targets -- -D warnings` → schoon.
- `cargo test -p burnburn-types -p burnburn-geometry -p burnburn-document -p burnburn-io` → alles groen (1 ignored: fixture-writer).
- `cargo tree -p burnburn-io -e normal,build`: geen `cc`/`cmake`/`-sys`; `cargo xtask layers` → no violations.

## Onbevestigd
- Duurzaamheid bij stroomuitval op echte hardware: niet getest. `MemoryFileSystem` modelleert alleen file-sync, geen
  directory-durability. `sync_file` = `File::sync_all` (volgens de std-implementatie `F_FULLFSYNC` op Apple; niet
  onafhankelijk gemeten).
- Windows: `rename`-over-bestaand, `sync_dir` (no-op) en bestandsvergrendeling zijn niet getest.
